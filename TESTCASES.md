# 1. Регистрация

## TC-REG-001 — Успешная регистрация нового пользователя

**Endpoint:** `POST /api/1/register`  
**Тип:** Позитивный, функциональный

**Предусловия:**
- Пользователь с выбранным username отсутствует.

**Тестовые данные:**
```json
{
  "username": "student_<unique>",
  "password": "strong-password"
}
```

**Шаги:**
1. Отправить POST-запрос на `/api/1/register`.
2. Передать username и password в JSON body.
3. Проверить HTTP status code.
4. Проверить тело ответа.

**Ожидаемый результат:**
- HTTP `201`.
- В ответе присутствуют поля `id` и `username`.
- `id` является целым числом.
- `username` соответствует переданному значению.

# 3. Контроль доступа (X-UserId)

## TC-ACCESS-001 — Попытка создать объявление от имени другого пользователя через X-UserId

**Endpoint:** `POST /api/1/item`

**Тип:** Негативный, безопасность

**Предусловия:**
- Пользователь A зарегистрирован и авторизован.
- Пользователь B зарегистрирован.
- Известен ID пользователя B.

**Тестовые данные:**
```text
Authorization: Bearer <token_A>
X-UserId: <id_B>
sellerID: <id_B>
```

**Шаги:**
1. Передать токен пользователя A. 
2. Передать заголовок `X-UserId` со значением ID пользователя B. 
3. Указать `sellerID` пользователя B. 
4. Отправить запрос создания объявления.

**Ожидаемый результат:**
- Запрос не позволяет создать объявление от имени пользователя B.
- `X-UserId` не используется для обхода проверки владельца.
- Возвращается ошибка авторизации или валидации.
- Объявление от имени пользователя B не создаётся.

---

## TC-ACCESS-002 — Попытка получить чужое объявление через X-UserId

**Endpoint:** `GET /api/1/item/{id}`

**Тип:** Негативный, безопасность

**Предусловия:**
- Пользователь A зарегистрирован и авторизован.
- Пользователь B зарегистрирован.
- Пользователь B создал объявление.
- Известны ID пользователя B и ID его объявления.

**Тестовые данные:**
```text
Authorization: Bearer <token_A>
X-UserId: <id_B>
id: <item_B_id>
```

**Шаги:**
1. Передать токен пользователя A.
2. Передать заголовок `X-UserId` со значением ID пользователя B.
3. Передать ID объявления пользователя B.
4. Отправить GET-запрос.

**Ожидаемый результат:**
- `X-UserId` не используется для определения текущего пользователя.
- Заголовок не предоставляет пользователю A права пользователя B.
- Результат запроса определяется Bearer-токеном пользователя A и правилами доступа API.
- Подмена пользователя через `X-UserId` невозможна.

---


4. Проверить ответ.

**Ожидаемый результат:**
- HTTP `200`.
- Объявление создано.
- В ответе присутствует UUID созданного объявления.

# 10. Сквозные сценарии

## TC-E2E-001 — Полный жизненный цикл объявления

**Endpoint:** `register → autorize → item → get item → statistics → delete`  
**Тип:** E2E, функциональный

**Предусловия:**
- Нет.

**Шаги:**
1. Зарегистрировать уникального пользователя.
2. Авторизовать пользователя.
3. Создать объявление.
4. Сохранить UUID объявления.
5. Получить объявление по UUID.
6. Получить статистику v1.
7. Получить статистику v2.
8. Получить список объявлений продавца.
9. Удалить объявление.
10. Проверить, что объявление удалено.

**Ожидаемый результат:**
- Каждый этап выполняется успешно.
- Данные, созданные на предыдущем этапе, корректно используются на следующем.
- После удаления объявление недоступно.
