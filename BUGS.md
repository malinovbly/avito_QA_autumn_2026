## Задание 2.1 (API)

### BUG-001 — Некорректный формат createdAt в ответе GET объявления

**Priority:** P2

**Endpoint:** `GET /api/1/item/{id}`

**Предусловия:**
- Зарегистрирован пользователь.
- Получен валидный access token.
- Существует объявление.

**Шаги воспроизведения:**
1. Отправить `GET /api/1/item/{id}` с валидным Bearer-токеном.
2. Получить ответ `200`.
3. Проверить поле `createdAt`.

**Фактический результат:**

API возвращает:

```json
{
  "createdAt": "2026-09-12 21:24:14.563352 +0300 +0300"
}
```

**Связанный тест:** `TC-GET-ITEM-001`, `TC-E2E-001`

### BUG-002 — Некорректный формат createdAt в ответе получения объявлений продавца

**Priority:** P2

**Endpoint:** `GET /api/1/{sellerID}/item`

**Предусловия:**
- Зарегистрирован пользователь. 
- Получен валидный access token. 
- У пользователя существует хотя бы одно объявление.

**Шаги воспроизведения:**
1. Отправить `GET /api/1/{sellerID}/item` с валидным Bearer-токеном.
2. В `sellerID` передать ID пользователя, у которого есть объявления.
3. Получить ответ `200`.
4. Проверить структуру ответа и поле `createdAt`.

**Фактический результат:**

API возвращает:

```json
{
  "createdAt": "2026-09-12 21:24:14.563352 +0300 +0300"
}
```

Значение не распознаётся как корректный `datetime` при валидации ответа по схеме `GetItemResponse`.

**Связанный тест:** `TC-SELLER-001`

### BUG-003 — Не возвращается 404 для несуществующего продавца

**Priority:** P1

**Endpoint:** `GET /api/1/{sellerID}/item`

**Предусловия:**
- Получен валидный access token.
- Пользователь с указанным `sellerID` не существует.

**Шаги воспроизведения:**
1. Отправить `GET /api/1/{sellerID}/item` с валидным Bearer-токеном.
2. В `sellerID` передать несуществующий ID, например 99999999.
3. Получить ответ сервера.

**Фактический результат:**

API возвращает: `[]` с HTTP-кодом `200`.

**Ожидаемый результат:**
- HTTP `404`.
- Пользователь с указанным sellerID не найден.
- Пустой массив не возвращается для несуществующего пользователя.

**Связанный тест:** `TC-SELLER-003`

### BUG-004 — Пользователь может удалить чужое объявление через X-UserId

**Priority:** P0

**Endpoint:** `DELETE /api/2/item/{id}`

**Предусловия:**
- Пользователь A зарегистрирован и авторизован.
- Пользователь B зарегистрирован и авторизован.
- Пользователь B создал объявление.
- Пользователю A известен ID объявления пользователя B.

**Шаги воспроизведения:**
1. Авторизоваться от имени пользователя A.
2. Получить ID объявления пользователя B.
3. Отправить DELETE-запрос с Bearer-токеном пользователя A.
4. Передать в заголовке `X-UserId` ID пользователя B.
5. Передать ID объявления пользователя B.

**Фактический результат:**
- API возвращает HTTP `200`. 
- Объявление пользователя B удаляется.

**Ожидаемый результат:**
- HTTP `400`.
- Пользователь A не может удалить объявление пользователя B.
- Заголовок `X-UserId` не должен позволять изменить пользователя, определяемого Bearer-токеном.
- Объявление пользователя B должно остаться доступным.
- Сервер должен отклонить попытку удаления чужого объявления.

**Связанный тест:** `TC-ACCESS-006`
